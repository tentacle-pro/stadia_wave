# Stadia Wave 产品文档

Stadia Wave 让 Google Stadia Controller 成为 Wi‑Fi 语音输入设备。用户按住手柄的 Assistant 键说话，在电脑上看到可编辑的转写草稿，再确认将文字输入目标应用。电脑也可以通过手柄震动提示有任务需要用户查看。

## 首版范围

Bridge 和 Companion 是两个可独立启动的程序。首版在当前 Apple Silicon Mac 上运行两者，使用已经验证的 Gotham 282115 手柄固件和 Stadiacast。Bridge 与 Companion 即使位于同一台 Mac，也走服务发现和网络连接。这条路径将来可以直接用在两台电脑之间。

| 应用 | 用户在这里做什么 |
| --- | --- |
| **Wave Bridge** | 首次配置 Stadiacast 路径和网络参数，启动服务，查看运行日志。Bridge 可以通过命令行配置和运行。 |
| **Wave Companion** | 发现并连接 Bridge，查看手柄与电量状态，选用语音识别引擎，编辑草稿，确认粘贴或触发测试震动。Companion 是日常交互入口。 |

首版验收集中在 macOS 上的语音输入和双向通信。树莓派、NAS、OpenWrt 部署，虚拟游戏手柄，实时转写，以及 AI 工具的真实任务接入留到后续。

## 初次连接

1. 用户用现有路由器配置为手柄下发 DNS，指向运行 Bridge 的固定局域网 IP。更换路由器或 Bridge 地址时，由用户更新这项配置。
2. 启动 Bridge。它在后台启动 Stadiacast，并将自身发布为一个可发现的服务。手柄开机后可以连接 Stadiacast。
3. 打开 Companion，从发现列表选择 Bridge。首次连接使用 Bridge 提供的配对信息，成功后记住该设备。连接双方在同一台 Mac 上时也走这个流程。
4. Companion 分别显示「Bridge 已连接」「手柄已就绪」与「震动可用」。发现列表为空时，可以手动输入 Bridge 的地址和端口，并查看局域网权限提示。

## 一次语音输入

1. 在目标应用放好光标，按住手柄的 **Assistant** 键。Companion 记住当前目标应用并显示录音状态。手柄的麦克风指示灯闪烁后开始说话。
2. 松开 Assistant 后，Bridge 等录音结束，将音频发给当前 Companion。Companion 识别后显示可编辑草稿。
3. 按手柄 **A** 或点界面的「粘贴」确认。Companion 将草稿粘贴到录音开始时记住的应用。无法确认目标应用或取得粘贴权限时，保留草稿并提供「复制」。
4. 按 **B** 或点「丢弃」取消当前草稿。语音识别失败时显示原因，并允许对已收到的音频重试。

只在草稿可操作时响应 A 和 B。文本由用户确认后输入，发送给 AI 工具继续由目标应用内的操作决定。首版提供一种在当前 Mac 上验证可用的 ASR，接收端结构允许以后切换系统识别、本地模型或商业 API。

## 连接接管

**一个 Bridge 同时只服务一个 Companion。** 已配对的第二个 Companion 主动连接时接管，Bridge 断开前一个连接。这个规则也适用于同一台 Mac 上运行的两个 Companion 实例。

| 场景 | 用户看到的结果 |
| --- | --- |
| 第二个 Companion 主动连接 | 第二个显示「已连接」，第一个显示「连接已被接管」。 |
| 第一个仍有已收到的草稿 | 草稿保留，可编辑和复制。手柄控制与粘贴操作随接管结束，用户可主动重新连接。 |
| 正在录音或传输时发生接管 | 这段未完成录音取消。新 Companion 等待下一次 Assistant 按下后开始录音。 |
| Companion 休眠或短暂断网 | 可以自动重连空闲的 Bridge。如果 Bridge 已被另一端使用，显示占用状态，等待用户主动接管。 |

## 震动与人工介入

Companion 提供「测试震动」按钮，经由 Bridge 让当前手柄短震。将来接入 AI 任务后，震动用于提醒用户查看待处理事项，详情和处理状态留在 Companion。用户确认已读和用户批准任务是两个不同的操作。手柄离线或震动通道不可用时，界面直接显示原因。

## 首版验收

- 两个程序在同一台 Mac 独立启动，Companion 无需填写地址即可通过网络发现 Bridge，完成配对并建立 WebSocket。
- 手柄连接后显示输入与录音状态。「按住说话 → 松手转写 → 编辑确认 → 粘贴」可完整走通。
- 从 Companion 触发测试震动，实物手柄给出短震。
- 用两个不同身份的 Companion 验证先后接管。包括录音中接管、旧端自动重连和旧连接的延迟指令。
- Bridge 和 Companion 可分别重启并恢复连接。网络重连时，已完成的粘贴操作保持单次提交。

连接与接管规则的实现见[技术方案](architecture.md)。
