# 手柄行为运行时

## 分阶段交付

第一阶段建立行为协议、确定性运行时、作用域资源管理、规则和脚本执行及热替换。用手写规则、脚本与现有默认映射做自动回归和真机测试。第二阶段在能力目录稳定后接入 Rig，整理知识、提示词、生成与验证工具和聊天流程。

本阶段脚本选用 Rust 内嵌的 Rhai，规则与脚本均返回声明式动作，由宿主统一校验和执行。脚本语言与宿主动作协议独立演进，后续可增加其他执行器。

## 数据流与职责

手柄事件经过连接与语音门控，再按优先级进入行为运行时。行为可以消费自己声明的输入，未消费的输入继续交给现有默认映射。行为与默认映射的输出共享宿主资源账本，最后由 macOS 适配层发送事件。

运行时位于平台无关的 wave-behavior crate。Companion 负责文件、用户操作、网络、权限与原生输出。Bridge 继续提供手柄事件。

## 首版协议

每个 JSON 行为定义包含 version、id、name、enabled、priority、inputs 和 program，并可声明 on_cancel 清理动作。id 为稳定的本地唯一标识。inputs 声明可消费的按钮或模拟输入。按 priority 降序分发，同优先级按 id 排序。

program 采用 rules 或 script。规则由触发事件、所需保持键和动作组成。脚本正文内嵌在 JSON，提供 on_event(event, state)，返回 handled、actions 和下一份 state。事件包含 input / tick 类型、按下和松开边沿、完整保持状态、摇杆、扳机、相对时间及帧间隔。

首版动作支持按下与释放键盘键、完整快捷键、鼠标左右键保持与释放、释放本行为全部资源、相对移动指针和滚动。键盘名称沿用 Companion 已支持的按键表。脚本状态为 JSON 数据，热替换后重新初始化。

## 路由与消费

处理成功且 handled 为 true 时，消费本行为声明的 inputs。持有按键或鼠标资源的行为在其作用期内继续消费声明的输入。低优先级行为遇到输入冲突时取消其活动状态和资源，之后重新等待触发。

脚本先计算结果，宿主在整批动作通过校验后提交。报错的行为释放已有资源并进入故障状态，本事件的声明输入由宿主消费。已失败的事件不会重放到默认映射。后续事件可以继续走其他行为和默认映射。

从行为路由回到默认映射时，对仍按住的按钮和仍偏离中心的模拟输入设置中立屏障，避免热停用或故障被解释为新的按压。

## 生命周期

行为状态为 disabled、active、faulted。先完成新定义的解析、能力校验和脚本编译，再替换旧定义。准备失败时保留旧版本。成功替换时释放旧行为资源，清空私有状态，由宿主等待输入回中后恢复。

每个行为是一个资源作用域。宿主管理该作用域的键盘与鼠标保持资源。两个行为持有同一按键时，最后一个持有者退出才发送释放。完整快捷键结束后恢复此前保持状态。

禁用只撤销对应行为资源。断连、所有者变化、语音接管、关闭总开关、睡眠时间跳跃和退出会清理全部输出及行为临时状态。故障和停用不阻断其他行为。on_cancel 在作用域仍持有资源时执行，首版仅允许释放动作及 Escape。应用切换脚本用它在异常结束时取消选择，正常松开仍由 on_event 确认。

行为开关控制这一份覆盖定义，不会关闭基础映射。禁用后仍可由其他有效行为或基础映射处理输入。若希望某个按键禁用行为后完全无动作，需将其基础映射设为「无动作」。当前两份示例的 X/Y 和 L1 动作与出厂基础映射相同，因此仅看动作无法判断执行来源，不能据此验收行为启停。

首版定时逻辑由 tick 与脚本私有状态表达，定时任务不会脱离行为作用域。

## 脚本执行约束

Rhai 仅接收事件与 JSON 状态，返回动作。宿主不注册文件、网络、进程和原生事件 API。禁用动态求值与模块导入，设置 20,000 步执行上限、50 毫秒进度检查预算，以及调用深度、容器和字符串大小上限，并限制每次返回的动作数、位移和状态大小。执行超限时按行为故障处理。

这些约束用于保证手柄事件循环可用。Rhai 执行资源预算需在真机上持续测量，后续若增加阻塞宿主能力，需要独立执行隔离和超时机制。

## 文件与操作

Companion 数据目录下 behaviors/*.json 保存定义，逐文件加载，首版最多 32 个文件。损坏文件单独报告。提供打开目录、重新加载、启停行为和安装手写示例的入口。示例安装默认关闭，用户启用后真机验证。首版通过重新加载进行热替换，文件监视可在后续增加。

坏文件和重复 id 不应使有效的旧行为失效。成功加载同一 id 的新版本时热替换。删除定义文件后重新加载会卸载对应行为。

## 手写验收用例

- JSON 规则将 X/Y 映射为鼠标左右键，按住拖拽，松开释放，验证默认映射不会重复点击。
- Rhai 脚本以 L1 建立应用切换模式，方向键选择、向下取消，松开确认。
- 禁用或替换一个持有修饰键的行为，确认释放后需要回中，其他行为继续运行。
- 故障脚本与无限循环脚本被停用，其他规则继续响应，本次事件无默认动作重放。
- 语音草稿出现时清理行为资源，A/B 由语音流程消费。
- 现有摇杆、扳机调速与默认快捷键继续工作。

## AI 阶段的接口准备

行为 Schema、能力目录、事件与输出记录、静态校验和模拟执行组成 Rig 助手的工具边界。先用人工编写的同一份定义完成验证，再将定义的生产者扩展为助手。模型生成流程与实时输入执行各自运行。

已实现的规则与脚本示例见 apps/companion/behaviors，协议类型见 crates/behavior/src/lib.rs。按键和鼠标资源管理见 broker.rs，Rhai 执行限制见 script.rs。

## 首版事件与脚本约定

按钮名为小写，摇杆推动使用 left_stick / right_stick，摇杆按下使用 l3 / r3。axes 顺序为左 X、左 Y、右 X、右 Y，范围约为 -32768 到 32767，Y 正值向上。triggers 顺序为 L2、R2，范围 0 到 255。

time_ms 是当前输入会话的相对毫秒时间，dt_ms 是本次 tick 的间隔。脚本使用这两个字段表达计时，Rhai 的系统时间能力关闭。每次调用只执行 on_event，顶层语句不参与运行。state 通过返回值显式传递，最大 16 KiB。单次最多返回 64 个动作，单个 Move / Scroll 分量上限 1000，必须为有限数值。

鼠标脚本或规则持有左键时，默认左摇杆产生正确的拖拽事件。行为键盘保持与默认映射共用引用计数。L1 脚本示例在按住方向键 450 毫秒后重复选择，间隔 100 毫秒，由 tick 驱动。

重新加载只替换发生变化的定义。无变化的行为继续保留状态和资源。行为停用先释放资源，再保存开关状态，磁盘写入失败也不会阻止本次停用。若定义文件有未加载的修改，界面提示先重新加载，避免开关操作覆盖用户编辑。
