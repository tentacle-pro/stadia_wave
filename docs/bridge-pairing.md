# Bridge 发现与配对

## 本机连接

默认 Bridge 只通过当前系统用户可访问的 Unix Socket 提供 Companion 连接。Companion 以本地 socket 为依据识别本机 Bridge，不从 Bonjour 地址或名称推断身份。本机连接不读写钥匙串，也不占用 TCP 8787。Stadiacast 的 DNS 服务独立运行。

## 远程发现与配对

显式启用远程访问后，Bridge 才监听 TCP 并广播 Bonjour。概览页列出本机及局域网 Bridge，远程首次连接在该列表输入配对码。后续可通过地址加入同一连接流程，前提是两端 IP 互通。

`wave-bridge pair` 由 Bridge 所在主机的服务用户执行，通过私有 Unix Socket 请求运行中的服务签发配对码。码只写到命令调用者的终端，短时有效，限制尝试次数且只可成功使用一次。重新签发或服务退出使旧码失效。服务自动重启不会开启配对窗口。

双方以经过审查的 PAKE 验证短码，并将握手绑定到 Bridge 长期 TLS 身份，再交付长期凭据。Companion 只在用户连接远程 Bridge 时访问其对应的钥匙串条目，首次配对前解释保存用途。Bonjour 结果不作为信任依据。

新配对成功并持久保存授权后，Bridge 撤销原远程 Companion 的授权，断开旧会话。生成新码、失败、过期及普通断开均不撤销授权。TLS 证书和私钥保持稳定。Companion 丢失凭据后，在 Bridge 上重新执行 pair。Bridge 不会从普通断开推断凭据丢失。

## 开发顺序

1. 本机 socket、独立本机发现及无钥匙串连接。
2. 本机 pair 命令与远程配对协议，实现配对码生命周期、身份绑定及授权替换。
3. 将远程配对交互迁到概览，移除旧配对文件入口，验证本机、局域网和凭据丢失恢复。

## 当前用法

默认启动使用本机 Unix Socket。桌面 Companion 查找默认目录。自定义目录需符合系统 Unix Socket 的路径长度限制。

以 `wave-bridge --remote` 启动可同时提供本机连接和远程 WSS，远程端口默认 8787。`--remote --port PORT` 可更改端口。开启远程访问后，在 Bridge 主机执行 `wave-bridge pair`，如服务使用自定义目录，签发命令应传入同样的 `--data-dir PATH`。在概览页点击远程 Bridge 行内的「连接」。Companion 这时才读取该 Bridge 的钥匙串凭据。如果凭据缺失或已被 Bridge 撤销，该行会显示「配对」。点击展开，输入八位码，再点击「配对并连接」。连接后可在同一行断开，连接过程中也可取消。码的窗口为五分钟，最多开始五次握手。短码模式启动时不会创建配对文件。

短码握手采用 [RustCrypto SPAKE2](https://docs.rs/spake2/0.4.0/spake2/)。Bootstrap WebSocket 交换 PAKE 消息以及证书和服务端证明。Companion 校验证明后才以该证书建立 TLS，完成配对所需的导出令牌只在这条连接中提交。窗口被重新签发、成功使用或服务重启时，其尚未使用的令牌一并失效。显式输入新码时跳过读取旧钥匙串项，以支持旧凭据失效后的换机流程。系统拒绝保存时保留当前连接，并提示下次需要重新配对。

单独传入 `--port` 仍启用旧配对文件模式，用于现有部署迁移。概览页依据发现信息显示对应输入框。手动输入地址仍待实现。
